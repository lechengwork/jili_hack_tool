# 696 機率介面更新 — 2026-09-21

> **給機率團隊。** 前一版是 09-11 那包。這次「迦樓羅的饋贈」五種效果**全部解完**，
> 其中兩種的槽位對應**我們之前給錯了**，還多了兩個**新欄位**。請整包覆蓋。

## 一、必須改的：`nudge_pos` 五格的正確對應

| 槽位 | 效果(遊戲說明頁) | 值 | **伴隨欄位** | 樣本 |
|---|---|---|---|---|
| `0` | ①挑 3~5 個倍率符號,顯著提高它們出現的概率 | 恆 `1` | **`gift_pool`(新)** | 3 |
| `1` | ②把特殊轉軸最終結果替換為所選符號 | 被替換掉的**原符號 id** | — | 2 |
| `2` | ③把最終倍率符號升級為更高的數值 | 恆 `1` | `boost_symbols` | 6 |
| `3` | ⑤把中獎倍數與轉輪另一格交換 | `1→idx0 2→idx1 3→idx3 4→idx4` | — | 11 |
| `4` | ④重轉一個轉軸,保證獲得更高的獎金 | **重轉第幾軸(1..3)** | **`respin_prev`(新)** | 3 |

### 三處更正(我們之前給錯)
1. **`index3` 是「交換」不是「升階」。** 舊版寫「值＝升了幾階」是錯的:8x 額外下注的局
   照升階算會得出 10x,但 8x 已把 10x 移出轉輪,不可能存在。11 局實證交換說零反例,
   前端動畫也確認是兩格對調。
2. **`index0` 和 `index2` 的效果對調了。** 你們原本 Go 註解的寫法是對的,我們中途一度改錯又改回來。
   判準:`gift_pool` 會讓**整個轉輪 5/5** 都從清單抽出(①);`boost_symbols` 只保證**最終那一格**
   落在清單內(③,轉輪其餘格 2~3/5)。
3. **舊的「3~5 個 vs 實測 2 個」矛盾解除。** 說明頁的「3~5 個」講的是 `gift_pool`(實測 3 個,符合);
   `boost_symbols` 屬於③,本來就沒有這個限制。

## 二、兩個新欄位(`math_696.proto` 已加)

```proto
repeated int32 gift_pool   = 9;   // 饋贈①挑中的 3~5 個倍率符號
repeated int32 respin_prev = 11;  // 饋贈④被重轉那一軸【重轉前】的 3 個符號
```

`board` 現在**固定**帶這兩個鍵(沒觸發＝空陣列),2062 個局檔已全部重產。

### ★`index4` 現在可以產了,但一定要帶 `respin_prev`★
之前那批 index4 會讓遊戲卡死(轉軸停住、不結算、按不了下一局),原因就是少了這個欄位 ——
前端要靠它演「重轉前 → 重轉後」的動畫。已用真封包回放驗證:帶了就正常演完。

```
實例 24265-607680-00700696
  nudge_pos   = [0,0,0,0,3]      → 重轉第 3 軸
  respin_prev = [0,2,3]          → 該軸重轉前 = J,K,A
  reels[2]    = [6,6,1]          → 重轉後 = 紅寶,紅寶,Q (reels 永遠是最終盤面)
  結果:兩條線本來都不中,重轉後各中 3 個 Q,贏 3.0
```
