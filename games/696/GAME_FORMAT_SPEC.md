# JILI 696 — 遊戲資料格式規格（前端 / RTP 使用）

> **遊戲**：JILI game **696** — *Fortune Garuda 500*（倍率轉輪 + EX NUDGE + 兩級額外下注，特色全在 base game，無獨立免費遊戲畫面）。
> **狀態**：`/fg5/req` 加解密與傳輸已 100% 破解並對真 WASM 端到端驗證；本文件是**應用層資料格式**（protobuf 明文結構），供前端渲染與 RTP 對數使用。
> **來源**：3+ 個已驗證資料點（中獎 / 沒中 / 兩級額外下注 spin）+ 真實 netlog 請求擷取。整合自 SCHEMA.md / REQUEST_SCHEMA.md / DECODED_RESPONSE_sample.md / PROTOCOL_SPEC.md。
> **傳輸/加密細節**：見 `../../PROTOCOL_SOLVED.md`（本文件不重複）。

## 0. 一頁速查

| 項目 | 值 |
|---|---|
| 端點 | `POST /fg5/req`（遊戲主迴圈，protobuf 請求 / 加密回應）；`WS /lifeservice/ws2`（保活，非遊戲邏輯） |
| 請求 | 明文 protobuf：`f1=seq, f2=動作, f3=token(20B), f4=client pubkey(32B)` |
| 回應（解密後） | protobuf `{f3=type, f5=data, f6=error_msg, f7=ret}`；`data` = 下列各 type 的遊戲負載 |
| 金額編碼 | 一律 **f64（double, wire type 1, little-endian）**，單位=幣值（例：`0.3`、`999977.6525`） |
| 單號編碼 | **varint（數字）**，顯示時才插 `-`（見 §6） |
| 省略規則 | proto3：**零值/空欄位整個省略**（win=0 → f3/f13 不存在；沒開額外下注 → f26 不存在） |

## 1. 訊息類型（回應 `type` = 解密明文 f3）

| type | 意義 | data 長度(樣本) | 何時出現 |
|---|---|---|---|
| **1** | **handshake config**（貨幣 / 餘額 / bet 選單 / 限額）✅ **已解** | 223B | 進遊戲握手一次（第一個請求） |
| **0** | **spin 結果**（盤面/中獎/餘額/單號） | 128–183B | 每次 spin |
| **2** | **餘額更新** | 15B | 餘額變動 / balance poll |
| **58** | **回合/session 資訊**（bet 範圍、時間戳、回合 id） | 67–69B | 進遊戲 / 回合 |
| 19 | 小狀態 | 2B | init |
| 10 / 21 / 25 / 27 / 33 / 51 / 60 / 69 | **init 序列 ack**（多為空 data；type 60 帶 `ret=801`） | 0B | init 握手序列 |

> ⚠ type 值採用「已驗證的回應外層欄位號 f3=type」。舊筆記寫 f1=type 是錯的（見 PROTOCOL_SOLVED.md）。
> **init 是有順序的腳本序列** — 同形請求（例如空的 keepalive）依位置拿到不同型別的回應。真實握手順序：`type 1 → 58 → 69 → 51 → 60(ret=801) → 19 → 58 → 58 → 10 → 21 → 33 → 25 → 27 → 2…`。mock 需**按順序重播**，不能只看請求形狀。

## 1b. handshake config（type 1，223B）

進遊戲第一個請求（120B，`f2` 含 f1..f5 裝置/語系）的回應。內容 = 遊戲初始設定：
- `f1.f3` (str) = 貨幣符號 `$`
- `f1.f4` (f64) = 玩家餘額
- `f1.f5` = **bet 選單**（packed f64 陣列）= `[0.3, 0.5, 0.8, 1.0, 2.0, 5.0, 10, 20, 30, 40, 70, 100]`
- `f1.f6/f7/f8` (f64) = `1.0 / 0.1 / 32.5`（限額 / 步進 / 上限）
- `f5` (msg) = 更多設定（分頁 / paytable 索引，逐欄待細解）

> 這份就是先前卡 MSG 999.2 的關鍵 — 遊戲拿不到它就 init 逾時。**現已離線解出並進 `responses.jsonl` / `init_sequence.jsonl`。**

## 2. 請求端 schema（明文 protobuf）

所有請求共通：`f1=seq`（序號）、`f3=token`（20B，整場固定）、`f4=client pubkey`（32B，整場固定，握手時建立）。

### 2.1 Spin 請求（核心）
`f2`（msg）：
- **`f2.f1` (f64) = 下注額**（玩家設定值，例 `0.3` / `100.0`）
- `f2.f25` (msg) = spin 選項 `{f1,f2,f4 全 0}`（疑似 自動/turbo/快速 旗標）
- **`f2.f26` (msg) = 額外下注（ante）**。**有此欄位 = 有開額外下注**；`f2.f26.f1` = 級別：
  - 無 `f26` → 一般 spin（沒開）
  - `f26={}`（空，f1=0 被省略）→ **1.5 倍**額外下注
  - `f26={f1:1}` → **8 倍**額外下注
  - 與回應 `f23.f26` **完全鏡射**

> **前端/mock 要點**：下注額與額外下注**每把 spin 都在請求裡**（`f2.f1`=bet、`f2.f26`=ante），server 直接讀，不需維護 session bet 狀態。

範例：
```
一般 spin (0.3):     f2{ f1=0.3,   f25={0,0,0} }              → 請求 76B → 回應 230B
8倍額外下注 (100):   f2{ f1=100.0, f25={0,0,0}, f26={f1:1} }  → 請求 81B → 回應 238B
```

### 2.2 其他請求型態
| 請求長度 | f2 內容 | 用途（暫定） |
|---|---|---|
| 120B | `f1:"OS X", f2:"zh-CN", f3:{chrome,151.0.0.0,zh-CN,1920,1080}, f5:"Macintosh"` | **init/handshake**（裝置/語系）→ 回應 327B = 遊戲設定 |
| 69B | `f1:"zh-CN", f2:2` | 最常見，週期性輪詢 |
| 67B | `f1:"zh-CN"` | 設定語系? |
| 62B | `f1:0` | 狀態 / ack? |
| 58B | 僅 `f1=seq` | keep-alive / ack |

## 3. 回應 type:0（spin 結果）— 完整欄位

> 金額全為 **f64**；標「沒中省略」者在 win=0 時整個欄位不出現。

### 3.1 頂層
| 欄位 | 型別 | 意義 | 備註 |
|---|---|---|---|
| `f1` | msg | **局面明細**（見 §3.2） | |
| `f2` | bytes | 空（用途未定） | |
| `f3` | f64 | **總中獎金額** | win=0 時**省略**；同 `f1.f13` |
| `f6` | f64 | **玩家餘額**（spin 後） | 例 `999977.6525` |
| `f20` | varint | **單號 / round id** | 顯示格式見 §6 |
| `f23` | msg | **下注資訊**（見 §3.3） | |

### 3.2 `f1` 局面明細（msg）
| 欄位 | 型別 | 意義 | 備註 |
|---|---|---|---|
| `f1[]` | msg | 各 reel 資料（每筆 `f1`=3~5 bytes 符號） | 每軸符號序列 |
| `f2` | msg | **盤面符號窗**，`f2.f1`=bytes | 例 `[11,9,10,9,9,11,9,9,12,20]`（見 §4） |
| `f6[]` | msg | **中獎線**：每條 `{f1, f2, f3=線號, f4 f64=該線最終中獎}` | **f4 已含 f12 倍率**；沒中整段省略 |
| `f7` | varint | **中獎線數** | |
| `f8` | bytes | 5 bytes（疑似 5 軸 nudge/倍率位置，例 `[0,14,0,0,0]`） | |
| `f12` | f64 | **倍率 multiplier**（nudge 後最終總倍率） | 沒中=2.0（輪面2x），20倍中獎=20.0；單線最終分 = base線分 × f12 |
| `f13` | f64 | 總中獎（同頂層 f3） | 沒中省略 |
| `f15` | f64 | `0.97`（固定？RTP 相關？） | 語意待確認 |
| `f18` | varint | **額外下注級別**（鏡射 f23.f26：1.5倍=1, 8倍=2） | 沒開省略 |
| `f19[]` | msg | 更多盤面/符號狀態（nudge 後） | |

### 3.3 `f23` 下注資訊（msg）
| 欄位 | 型別 | 意義 | 備註 |
|---|---|---|---|
| `f23.f1` | f64 | **base 下注額** | =`0.3`；**額外下注時這裡仍是 0.3**，不是實付額 |
| `f23.f25` | bytes | 空，固定出現 | |
| `f23.f26` | msg | **額外下注/ante**（存在=有開） | `f26.f1`=級別索引：省略/空=1.5倍，`{f1:1}`=8倍 |

## 4. 盤面與符號

- 盤面符號以 **符號 ID 陣列**表示（`f1.f2.f1` = bytes，每個 byte 一個符號 ID）。
- 已觀察到的符號 ID：**9, 10, 11, 12, 14, 20**（例盤面 `[11,9,10,9,9,11,9,9,12,20]`、`[12,11,10,14,9]`）。
- 每軸資料在 `f1.f1[]`（每筆 `f1` 3~5 bytes = 該軸的符號序列）。
- **符號 ID → 視覺/賠付**：對應表在 astarte2 遊戲設定內（前端精靈圖集 `smallicon/ItemCards/696_cn.plist`，frame 命名 `31696..38696.png`；圖集編號與 protobuf 符號 ID 非同一套，需以 JILI 官方 paytable / 遊戲 config 對照）。**RTP 對數請以 JILI 提供的 696 數學表為準；本協定只負責傳輸符號 ID。**
- 特色：**倍率轉輪**（`f1.f12`）+ **EX NUDGE**（`f1.f8`/`f19` 記錄 nudge 後狀態）+ **兩級額外下注**（1.5x / 8x）。無獨立免費遊戲畫面。
