# 696 → 807 欄位定義對照

本表區分「可參照的玩法定義」與「不能直接複製的 wire 結構」。696 以 `fg5_696.proto` 及最新修正 `CHANGELOG_0921.md` 為依據；舊註解若與該修正矛盾，以修正及實際封包為準。

## 五種成功饋贈槽位

| index | 696 定案定義 | 807 可沿用的語意底稿 |
|---:|---|---|
| 0 | 提高選定倍率符號的出現率 | f13[0] + f14 倍率池；已做轉輪清單比對及使用者演出對照 |
| 1 | 替換原最終符號 | f13[1]；使用者觀察到手上方塊選取，結果換成 Ex Nudge。參數作原符號 ID 的解釋符合現有樣本 |
| 2 | 升級最終倍率符號 | f13[2] + f15；已有三筆結構案例及50→100直接演出確認 |
| 3 | 與轉輪另一格交換 | f13[3]；位置參數沿用 1→0、2→1、3→3、4→4 的候選對照，需區別失敗演出 f17[3] |
| 4 | 重轉一軸 | f13[4] + f16；值作軸號、清單作舊軸三格的解釋與 696、807 現有結構一致 |

這些定義可作命名依據，不必為每個合法參數都等一遍才承認欄位用途。樣本尚未覆蓋的組合、成功／失敗細節仍保留驗證範圍。

## 807 不能從這份 696 proto 直接搬過來的部分

- f6/f7 的 SymbolCount 清單、f8 的多段追加次數、f9 的逐次空內容，屬於目前已觀測的 win_type=5 路徑。已有 f6+f7 共八筆、選中 Ex Nudge 次數與 f8、f9 筆數及轉輪長度對應的案例；696 現有 proto 沒有這組已定義對照。
- f9 在 807 **不是 696 的 gift_pool**。807 的池是 f14，且 f9 已有同局出現兩次的證據，不能用單筆 presence 表示。
- f17 是另一組五格資料。使用者直接核對了 index1 的替換未成功，以及 index3 的交換未成功；696 目前這份 proto 沒有已明確定義的對應，不能刪除或與成功槽合併。index4亦已確認第三軸實際重轉但沒有派彩；index0缺直接失敗畫面、index2未出現非零案例。
- 807 的 Ex Nudge 符號為21，696為20。不能複製整張符號對照而不檢查。
- 本批派彩已確認 symbol1、symbol2 的倍率分別為2、3.5，與696既有2.5、4不同。
- 普通模式在807已有成功槽與其他演出槽的案例；不能照搬696那批普通模式298局零饋贈的抽樣結果，作為功能禁用規則。

## 696 舊檔本身的問題

目前倉庫內 `games/696/math_696.proto` 編譯會失敗：Board 中 nudge_pos 與 gift_pool 重複使用欄號9，window_extra2 與 respin_prev 重複使用欄號11。這是舊檔的維護問題，不是807玩法差異。

本次只核對並記錄此問題，沒有修改696既有介面。807更新時應使用自己的唯一欄號與編譯驗證；定義相通不代表能原檔照貼。

## 807 原生規則來源已確認

使用者確認三張新說明圖全部來自807，完整整理見 `RULES_807.md`。807明寫相鄰兩軸鎖定、剩餘一軸重轉後可保持原結果，故不可直接沿用696舊註解的「保證更高獎金」描述。此差異不否定共通槽位結構，但需要修正重轉結果語意。

## 成功升級已取得直接演出確認

單號 `2485947667000270807`：使用者明確指出動畫丟出倍率，使50×變100×，與交換演出不同。封包為 f13[2]=1、f15=[17,18]（50×、100×）、最終倍率100，f13[3]=0且f17全零。因此成功升級與成功交換應分別定義，不能合併為一種「換倍率」。
